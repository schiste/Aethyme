# D10 TypeScript identity parity

Last Updated: 2026-10-16

This directory is a finite, arm's-length TypeScript qualification harness for the Local D10 identity contracts. It lives under `packages/aethyme-eval`; it is not a production TypeScript consumer and is not an Aethyme eval target. It uses Node built-ins and the reviewed T01 canonical JSON module, with no external assets or dependencies.

## Qualification coverage

The finite harness checks descriptor canonical bytes and immutable RecordId, enrolled/proposed FileIds, source snapshots, raw-path ordering, explicit Rename identity preservation, Copy/Split/plain-new ordinals, immutable ContributionRevision IDs, and no-hash validation refusals. It consumes both the generic `proposal-new-file` seed golden and the ContributionId-bound seed golden. Source paths match Rust `SourceSnapshot::new`: the 4096-byte cap, raw-byte component checks, protected `.git` aliases (case, HFS-ignorable, NTFS stream/trailing-dot/space and 8.3 forms), duplicate paths, and file/directory-prefix conflicts. Snapshot path sets are preflighted before the adapter hashes content or identities. The final profile mirror checks ProjectDescriptor's 4096-file and 1 MiB canonical-byte limits, plus ContributionRevision's source-change, dependency, file-reference and 1 MiB canonical-byte limits before minting a RecordId. `source-pins.json` covers the exact Rust source set, TypeScript source set, and 20 frozen vector files, and binds the Rust contract source commit.

## Final profile adaptation (UNRUN)

The TypeScript adapter and generated boundary assertions now mirror the frozen contract profile at `01258cbc8c3e223ebbe01c9fe19e9c5bc6dbba7a`: descriptors and revisions are limited to 1 MiB canonical bytes, descriptor files and revision changes/dependencies/file references are limited to 4096 entries. The 4096-file descriptor boundary is generated with short paths and stays below 1 MiB; the 4097-file case is also below 1 MiB so it isolates the count refusal. A second generated descriptor reaches 1,659,315 canonical bytes with 4096 100-byte paths. ContributionRevision tests accept 4096 dependencies and references, reject 4097, and exercise document admission with generated 123/124-change cases of 4096-byte paths (1,041,525 and 1,049,989 canonical bytes). A 4097-change input is larger than 1 MiB even with minimal valid changes, so its assertion checks the Rust error precedence: `too_many_changes` before byte admission. The generated cases do not alter the 20 frozen fixture files.
