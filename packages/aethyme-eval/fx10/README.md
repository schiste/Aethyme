# FX10 sustained-arrival Playground

This fixture freezes six independently maintained route features and one shared command contract for the Local controller sustained-arrival qualification. The older ready group is A-alpha, B-beta and C-gamma; they form one required atomic unit. D-delta, E-epsilon and F-zeta are later compatible singleton submissions. Every submission changes one feature module, so the same independent behavior oracle applies to both accepted waves.

The contract, source files, per-submission replacement bytes, gate-child handshake, proxy, oracle vectors and expected transcript are immutable qualification inputs. `proposal-manifest.json` binds their byte digests and the arrival schedule. The actual harness must verify those digests before starting Docker or Git acceptance.

The controller receives A-C as individual persisted availability events; the observer never calls wave admission. It discovers the controller-created wave and native gate job by exact target, revision and authority epoch, and derives readiness from their persisted arrivals. The gate first contends on a real host-resource capacity lease with a five-second wait bound. After the holder releases, the observer verifies the separate native gate lease is active and waits for the fixed gate child to publish its PID and heartbeat markers. D-F arrive while that child remains alive; the observer confirms A-C remain the exact active wave and the target remains Verifying with no completion, then observes advancing heartbeats during a bounded 250 ms window before releasing the child to execute the real source-integrity checks. The report records the actual lease wait and gate-child lifetime. The later wave accepts D-F without cancelling or restarting A-C.

A separate bounded negative schedule uses a second disposable target and bare remote. Its controller-created A-C wave is observed by exact target, revision and epoch. The actual gate waits behind a typed one-unit capacity hold, then obtains its separate pool lease and starts the fixed gate child. The observer requires advancing child heartbeats during a bounded 250 ms window immediately before the update, advances the remote's accepted ref once with a fast-forward commit that retains the same source tree, records the confirmed ref move, and requires an additional bounded 250 ms of advancing child heartbeats before release without releasing the child between windows. The real verifier must pass against the now-stale candidate, and the one finite publication attempt must fail safely. Incremental report events retain the actual ref tips/tree, holder release, child, verifier receipt and transport result even if a later assertion fails. The fixture never injects a completion, verifier result, or provider receipt.
