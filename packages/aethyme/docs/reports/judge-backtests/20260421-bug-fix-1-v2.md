tie threshold — neither judge is empirically superior against our

## Observations

1. **Both judges systematically over-score** vs the keyword rubric (9/10
   sample means above anchor). This is expected: judges reward
   paraphrased substantive correctness that keyword matching misses.
   It's what we want from a judge; it's also why the rubric anchor
   measures *rubric-alignment*, not truth.
2. **Codex has tighter intra-rater consistency** (mean stdev ~3.7 vs
   ~5.1 for claude-haiku) — more deterministic scoring on repeat.
3. **Claude-haiku has slightly narrower drift distribution** — its worst
   item (12.0) is lower than codex's worst (12.8).

## Decision

**Do not flip DEFAULT_BACKEND.** The empirical evidence doesn't justify
a change; claude-haiku wins by 0.5pt, well inside the 2pt tie threshold.

**But** — claude-haiku is validated as a first-class alternative. It
should be used whenever:

- The agent population being judged includes Codex (self-preference
  bias is plausible but not empirically detectable via rubric anchor)
- A second opinion is desired (set `judgeBackend="claude-haiku"` on
  `RunRequest` for one run, compare against codex on another)
- Ensemble judging is being evaluated (future work)

## Bugs fixed by this back-test

The first run uncovered two integration bugs in the claude-haiku
backend that unit tests missed:

1. **stdout-redirect race** — `claude > output.json` streams into the
   file while `_wait_for_output_file` polls for existence, so partial
   JSON was being read. Fixed via atomic `> OUT.partial && mv` pattern.
2. **`--bare` + keychain** — `--bare` skips keychain reads along with
   hooks/MCP/CLAUDE.md, which breaks OAuth auth. Flag removed; trade-off
   is ~70k extra input tokens per call for context auto-load.

Both fixes landed before the v2 run that produced this result.

## Future work

- **Add more calibration items** spanning a wider score range (current
  set is all 40-50). A 5-item set at 80+ and a 5-item set at <30 would
  let us detect judges that drift asymmetrically at the extremes.
- **Human-anchor at least 2 items per eval type** so we can detect when
  the judges are systematically wrong-but-rubric-aligned.
- **Re-run on a different eval type** (e.g. `explain-repo` or
  `dead-code`) before concluding claude-haiku is safe as a default.
- **Track judge-vs-rubric gap as a monitored signal.** A sudden
  convergence onto the rubric would mean the judge stopped rewarding
  paraphrased correctness — a regression.
