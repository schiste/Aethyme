# Local v3 compatibility qualification

Last Updated: 2026-10-11

Issue #681; §6.8–6.9/6.19; D18/D32/D33/D36; T33–T35/T57/I01–I02.
This draft begins the executable compatibility matrix. The contract below is
not passing qualification evidence; implementation and captured runs follow.

## Existing entrypoints

Collaboration disabled preserves the legacy command's output, policy, resource
and network behavior. Advisory capture failures preserve the legacy result and
report the capture failure separately. Required capture refuses before the
consequential operation. The approved schema/configuration fence prevents an
old binary acknowledging unsupported policy while legacy-only repositories
remain usable. Unknown collaboration keys retain the approved required versus
advisory behavior.

Retained state remains outside legacy cleanup reach. Unsafe shared-clone/root
combinations refuse with a separate clone/state location or historical-export
action. Migration refusal must preserve existing data. Qualification uses the
actual installed pre-stack binary at source commit
`5e8daf712e26c63f1d4082e9a617f556cf995de2`; record its exact executable digest and
environment before each accepted run rather than treating current code as an
old implementation.

## Independent Local work

Unavailable optional peers do not prevent Local retention, bounded context,
controller work or authorized configured Git publication. Offline metadata is
not currently visible evidence. Unknown native acceptance does not silently
select a different provider or a local fallback. Required reviews and current
verification policy remain required on the configured route.

Optional absent/stale/failed analysis retains explicit incomplete or unavailable
coverage and causes no implicit installation. Unknown schemas and unsupported
profiles refuse optional results; partial/shallow bases and unsupported path,
filter or submodule cases retain exact diagnostics and the legacy path.

## Rebinding and historical restore

A receiving project checks the independent bundle digest, origin, visibility
and audience, then appoints its own native authority/epoch. Imported source and
past records remain separately indexed history. They cannot revive producer
permissions, acceptance, active assignments or cursors. Pending uncertain
publications remain retained and require reconciliation before dependent work.
A source-only private rehearsal establishes bytes, not current acceptance or
lossless migration of every provider artifact.

## Required evidence

Run finite positive and negative schedules against disposable Playground
repositories. Include disabled parity, actual old-binary refusal/cleanup,
network-denied Local source/Git paths, schema negotiation/refusal, root safety,
and independent receiver rebind. Record source/environment/commands/output
digests and limitations. Each introduced correction gets a reachable guard
removal and an independent private adversarial review. E1 composer evidence,
native gate integration and live remote provider qualification remain separately
owned or configured prerequisites and are not inferred from these tests.
