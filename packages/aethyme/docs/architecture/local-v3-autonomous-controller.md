Last Updated: 2026-10-15

## Appointment and authority

An explicit operator appointment freezes target revision and epoch, objective,
finite cycle/completion/deadline allowances, wave policy, execution recipe,
existing verifier generation/policy and a local bare Git destination. The CLI
uses an existing broker session and producer appointment. It creates no verifier
trust, provider policy or model authority.

Durable arrivals and timed ticks share the bounded service loop. A frozen wave
keeps its members; later arrivals cannot restart its age or join its candidate.
Subsequent waves use the last privately accepted source and exact accepted
commit. All constituents remain in dependency checks, independent obligations
and provenance; composition applies only new deltas. Recipes require the
accepted-baseline-v1 capability. Older readers and the bounded resolver refuse
that separately appointed composition profile.

The local destination is checked as a bare repository and pinned before
admission. The retained descriptor binds the original and canonical path and
filesystem identity; the service checks it again before publication. Linked
worktrees, non-bare destinations and changed path identity refuse this profile.
The host and provider configuration are trusted; a hostile administrator racing
the final check is outside this guarantee.

## Dispatch, observation and completion

Every dispatch requires current authority and a finite reservation. Durable run
and service journals precede external work. A previous dispatch, including an
interrupted one, requires explicit reconciliation. A completed native job is
historical evidence and cannot authorize a new execution; dispatch claims its
prepared state atomically.

The driver checks cancellation, deadline, epoch and revision between stages and
at completion. Native gate observations cannot supply independent verifier or
provider authority. A policy with no native commands requires explicit
`allow_empty_native_gates`; artifact verification and fresh provider acceptance
remain mandatory.

Only a fresh publication dispatch with status `Succeeded` can continue. Failed,
prepared, running, ambiguous and reconciled historical outcomes hold for explicit
reconciliation. The driver then inspects the exact source route and requires
available, content-checked bytes at the candidate commit. A later availability
observation cannot settle an ambiguous managed write.

Completion consumes the existing private acceptance grant, rechecks current
verifier/provider guards, binds the transport intent to the wave, and records
publication confirmation and delivered members atomically. Historical receipts
supply no future authority. Independent roots retain completion provenance;
unknown consumption retains roots and reservations. Stop prevents further
managed dispatch while cancellation/recovery keeps lingering work visible.

The controller migrations require collaboration schema/floor 22. Migrations
19 and 20 adopt existing controller tables without deleting retained rows. The
aggregate Local branch uses schema/floor 23, whose native-job migration adds the
irreversible root-release witness. Migration controls preserve completion,
dispatch and root sentinels.

## Resource and deadline limits

Trusted control work reserves and charges a conservative 512 MiB memory,
768 MiB disk, one-slot and appointed time envelope. This is accounting rather
than measured host consumption or a hard host quota. Docker build and verifier
workloads have their separate enforced envelopes and use the shared coordinator.

The driver has stage-boundary deadline checks; existing native gate commands
retain their own finite deadlines. Optional graph preparation is refused because
it lacks this process deadline. This profile does not promise a hard deadline
covering all materialization and host operations. Budget/capacity holds,
unsupported cases, conflicts and exhausted allowances remain distinct outcomes.
