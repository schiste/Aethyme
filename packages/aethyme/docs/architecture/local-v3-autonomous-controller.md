# Appointed autonomous Local controller

Last Updated: 2026-10-12

Implementation in progress. This package completes the reference driver with
one explicitly appointed native execution path. It reuses retained capture,
finite Local waves, current authority, project reservations, native gates,
Docker supervisor, independent verifier and fresh source acceptance.

## Intended contract

An appointment freezes the selected target, objective, finite cycle/deadline
allowance, wave policy, execution recipe, exact verifier producer/policy and
authorized source transport. No implicit model, provider, policy trust or live
repository appointment is inferred. Durable arrivals and timed ticks use the
same bounded service loop. A wave freezes its members; later arrivals cannot
restart its age or join its candidate.

Every execution and verification dispatch requires an existing finite budget
reservation and current authority. Native gate results remain observations;
they cannot supply independent verifier evidence or source acceptance. Only
the existing verifier and current provider acceptance APIs can authorize the
exact candidate. A crash, missing response or unknown consumption retains its
roots and reservation and enters an explicit reconciliation hold.

Stop prevents further managed dispatch. Existing executor cancellation and
resource recovery retain visibility of lingering work. Budget/capacity holds,
unsupported cases, conflicts and exhausted allowances remain distinct terminal
or waiting outcomes. The controller does not merge a GitHub pull request or
change acceptance policy.

## Required qualification

An actual autonomous supported positive and sustained-arrival service schedule
must run locally. FX17 requires at least twenty accepted controlled changes,
later edits near earlier obligations, independent surviving-obligation checks,
and separate final held-out model cases. Preserve the complete schedule,
attempts, exclusions, failures, unknown consumption and actual costs. State
tests or a manually driven native path do not qualify autonomy.

The completion integration consumes the existing private acceptance grant,
rechecks its current verifier/provider guards, binds its transport intent to
the exact wave, and atomically records publication confirmation and delivered
members. Its historical record confers no future authority. Schema 19 adds
independent completion roots; the compatibility floor is also 19.

Two local controls pass: every historical identity changes the canonical
record ID, and public transitions still cannot manufacture delivery. The
first compile/test failures are retained. This is a foundation checkpoint:
the automatic dispatch/service loop and FX17 are still unrun and unqualified.
Generation preparation currently consumes its private grant before completion
because existing generation/verifier APIs require the verifying phase. Coordination and Git Platform remain outside this Local package.
