## Why this matters

This was a working agent-comparison benchmark harness with unusually
serious statistical and anti-bias discipline. Two future consumers:

1. **#28 acceptance harness** — the navigation_ctf / explain_repo evals
   were the agreed proof (or refutation) that cross-file caller edges
   improve agent navigation. Rebuild from this document when #28 lands.
2. **Any future agent-comparison benchmark** (broker A/B, vendor
   comparisons): the design knowledge below is tool-agnostic.

## 1. Experimental design (the invariant everything rests on)

**Treatment and control receive byte-identical prompts; only the
environment varies.** Control's playground clone has no tool artifacts;
Explore's clone has the skill deployed. This is the only way to
attribute a score delta to the tool rather than the prompt. Prompt
char-counts per arm were logged specifically to audit this invariant.

**The condition chain** (each step isolates one effect):

| Condition | Isolates |
|---|---|
| control-cto-off | Raw LLM, uncompressed terminal — the true baseline |
| control-cto-on | The Chau7 CTO (terminal-compression) confound, quarantined |
| explore | Environment help alone (deployed skill, no prompt hint) |
| leverage | + a minimal generic pointer ("SKILL.md exists; verify output before acting") |
| task-conditioned | + task-specific pre-computed context |
| negative-context (opt-in) | Loading cost vs misdirection cost of a *plausibly wrong* context |

Baseline for all deltas: `control-cto-off` (fallback `control`).
Optimization order that was settled: strengthen explore first, keep
leverage minimal-generic, defer task-conditioned — "if the generic base
is weak, task-conditioned just hides it."

**Negative-context plausibility contract** (trust-calibration
measurement, mirrors production staleness): a wrong-context candidate
must be (1) shape-identical in top-level keys, (2) within 2.0× size
either way, (3) same repo, (4) anchor-**id** overlap ≥ 0.30
(per-direction real∩cand/real, not Jaccard; symbol-level ids, not file
paths, so it works across languages), (5) not identical. Generated by
the production context generator against a *sibling task* (aim for the
30–50 % identifier-overlap band). Distinct `PlausibilityError` lets the
orchestrator skip the condition instead of failing the eval.

## 2. Architecture: plan generator + external executor

`generate_run_plan(...)` was a **pure function** returning
`{meta, paths, phases}` — no I/O, no agent launches. An external
orchestrating agent executed the phases mechanically via Chau7 MCP.
Purity made plans snapshot-able, diffable, testable. Phases:

1. **validate** — preflight: control clone has *no* `.codex/skills`;
   tool clone has the skill; engine binary exists; **no globally
   installed skill** at `~/.codex/skills/…` (would contaminate control).
2. **build-inputs** — one CLI command generating prompts/schema/context
   (moved off inline `python -c` after em-dashes in task strings broke
   shell quoting repeatedly).
3. **warm** — idempotent (`status || start && poll-log`), bounded
   (240 s), emits a **no-op phase** when the tool has no warm step so
   phase count stays stable across tools. Cold-start data justifying
   it: MediaWiki ≈108 s map build. Tools with per-repo on-disk state
   (graphify's ~225 MB `graphify-out/`) needed *inline* warm during
   build-inputs, then **copy** the state dir to sibling clones —
   copying guarantees bit-identical state so eval variance can't be
   blamed on tool nondeterminism.
4. **launch** — per-condition Chau7 tab; Claude with explicit
   `--session-id <uuid>` for deterministic collection; Codex with
   `--output-schema`/`--output-last-message`.
5. **monitor** — **file-first completion** (see §6).
6. **collect** — tab output + session JSONL + telemetry; writes
   attribution-confidence + completion-provenance artifacts.
7. **score** / 8. **report** ("NEVER hand-write markdown reports") /
9. **cleanup** — force-close every tab (limited tab pool).

Run-dir slug: `{ts}-{target}-[{scenario}-]{type}-{model}[-{reasoning}][-{tool}]`
— tool suffix omitted only for the self-tool; competitors always
explicit. A `AETHYMEBENCH_SELF_TOOL` env var centralized "which tool is
the subject" so the framework forks cleanly.

Safety timer: prepared benchmark clones self-delete on a 15-minute
`threading.Timer` unless the launch phase cancels it (5 min proved too
short mid-debug); the notice prints to **stderr** (stdout broke
`--json-output | jq`).

## 3. Scoring model

**Two numbers, never collapsed:** `quality_score` (0–100 weighted
rubric — task success) and the control-relative composite:

```
global = 100 + quality_delta_vs_control
             + 10·ln(token_ratio) + 10·ln(time_ratio) + 5·ln(cost_ratio)
```

ratios = control/condition, so 100 = parity and cheaper/faster only
helps *after* the quality comparison.

- Every rubric is a `weights` dict asserted to sum to 100. Component
  scorers: set-overlap recall on normalized paths; ordered-list
  (exact 1.0 / out-of-order 0.5); exact-path binary; relationship-chain
  as `(from,to,relation)` triple overlap; keyword-fraction for prose.
- **FAIL→PASS objective core** for bug-fix: the dominant weight (60) is
  the planted test flipping red→green with previously-green tests
  still green — an *empirical* signal, not output comparison.
- Efficiency curve: `ref/(ref+cost)` — smooth, cost=ref → 0.5;
  reference_cost is per-eval "par". Cost is the only metric comparable
  across backends (normalizes caching, token types, pricing).
- **Score twice — raw and path-normalized** — and report the
  `normalization_delta` plus counts of absolute-path/markdown-link/
  line-anchor issues, so sloppy formatting cost is visible instead of
  silently forgiven or punished.
- Keyword scorer strips prompt words >5 chars from the output first
  (stops task-conditioned prompts inflating their own score) and
  collapses whitespace (PTY noise splits keywords).
- Rolling baseline: control-relative scores used the **median of the
  last K=10 successful control-cto-off runs** keyed
  `(model, eval_type, target, scenario)` (≥3 required, else co-run
  control) — one unlucky co-run control otherwise shifts every derived
  score.

## 4. The three eval types

- **explain_repo** — reference derived from engine inspection (areas,
  entrypoints, docs, configs, navigation order). Gate: primary-language
  identification.
- **navigation_ctf** — the clever one: **the CTF is built from real
  graph relations, not authored**. Walk inspection output for a config
  with both an `entrypoint_for` code target and a `configures` area;
  synthesize the task from those edges; the reference *is* the edges.
  Hard rule: `task_spec` (agent-visible) and `reference` (scoring-only)
  are separate dicts and the reference must never reach any
  agent-facing artifact.
- **bug_fix** — deterministic planted bugs, idempotent plant, empirical
  `verify_setup` (planted test must FAIL, others PASS). The
  cross-package scenario plants the test 4 import-hops from the bug and
  gives only a behavioral symptom — measuring navigation, not fix
  difficulty. **CASL gotcha:** never plant on `manage` implications —
  CASL treats `manage` as a wildcard so the bug is invisible at
  `ability.can()`; use a non-wildcard action (EXECUTE→READ).
  Per-condition `git clone --local` prevents cross-contamination;
  `pnpm install --frozen-lockfile` done in prepare because the Codex
  sandbox blocks network.

## 5. Competitive benchmarking (ToolAdapter + TOML manifests)

A structural `Protocol` (`version/install/warm/implements/run_condition`)
+ a manifest-driven adapter, so Aethyme and competitors run under one
identical protocol. Adapters never see agent output — setup only.

Manifest essentials: `[source]` git+pinned ref (or `in_tree`);
`[install]`/`[register]` command arrays; `[version]` output contract
`"<name> <id>"` (prefix load-bearing); per-condition blocks where
explore's command is *optional by design* (it's the discoverability
test); `[prompts]` required iff leverage/task_conditioned declared;
`[notes].condition_mapping` **mandatory** — deliberate friction forcing
every manifest to articulate how its modes map onto the protocol, so
asymmetries surface at review time.

**Two strictly separated substitution regimes** (mixing them was "a
load-bearing bug"): shell-quoted command/path placeholders
(`{{TOOL_ROOT}}`, `{{TOOL_PYTHON}}` — venv python if present else
`sys.executable`; `{{TARGET_REPO}}`, `{{TASK_SHELL_ESCAPED}}`) vs
never-quoted prompt-text placeholders (`{{TOOL_NAME}}`,
`{{SKILL_PATH}}`). `workdir` values are never quoted (they go to
`cwd=`, and quoting corrupts paths with spaces).

Worked example (graphify): pin PyPI version and git ref together as the
audit trail; drop an ignore file so mixed-tool clones don't index the
other tool's SKILL.md; neutralize its LLM-coupled step to keep warm-cost
apples-to-apples; verify flags against `--help`, never the README
(README lied about flag shapes).

## 6. Running terminal agents (the operational canon)

- **Never trust tab/agent status for completion.** Codex tabs report
  `running` for their whole run; two tabs were observed reporting the
  same session id. The deliverable is a **file**: prompt instructs
  "save to `<out_path>`", completion = file exists AND ≥64 chars AND
  mtime quiet ≥3 s (stability gate against half-written reads). Atomic
  writes everywhere (`X.partial` → rename).
- **Attribute transcripts by content-match**, not reported session id:
  regex the out-path marker from each candidate JSONL's first user
  message; newest mtime wins; record `attribution_mismatch` and let the
  content match override — keep the disagreement as an audited
  artifact, don't hide it.
- Fresh tab per unit of work; ~**5 concurrent MCP-controlled tabs** is
  the practical ceiling (8 hard max); clean stale MCP tabs before a
  run; force-close all tabs after.
- JSONL metrics: sum usage over assistant messages, count `tool_use`
  blocks (minus the Agent meta-tool), **recurse into
  `<stem>/subagents/*.jsonl`**, duration = last-assistant −
  first-user timestamps.
- Everything **fails soft with an `error` field** — a broken judge,
  probe, or MCP call never fails the measurement.

## 7. LLM judge (bias-controlled)

- **Cross-family judging is the primary self-preference control**
  (Panickssery 2024, Stureborg 2024): never judge Codex agents with a
  Codex judge. Backends pluggable; a calibration back-test picks the
  lower-drift backend.
- **Envelope scrubbing before judging**: self-preference bias operates
  through *stylistic familiarity* — terminal chrome is a model
  signature. Line-anchored conservative regexes: drop provider
  boilerplate lines, strip chat prefixes (`Claude:`, `●⏺` bullets, REPL
  prompts). Applied before truncation (24 k chars, head+tail kept);
  scrubber returns stats so you can see it isn't eating content.
- Judge prompt: instructions + task + reference JSON + rubric +
  candidate; banded 0–100 scale; key directive "judge SUBSTANCE, not
  format". Schema-enforced output
  `{score, rationale, key_matches, key_misses}`.
- **Consistency ≠ accuracy.** N=3 samples per candidate →
  `mean ± stdev`, `reliable = stdev < 10`. Separately, hand-scored
  anchor items measure **drift** = |judge − human|; pass gate
  max ≤ 15 and mean ≤ 10. A judge can be stably wrong.
- Reject candidates < 50 chars; degrade soft (`{mean_score: 0, error}`).
- Claude-as-judge gotcha: `--bare` skips keychain reads and breaks
  OAuth installs; accept the ~70 k-token context cost and contain it
  with a forced output schema + disallowed tools.

## 8. Leakage (pretraining-contamination) probe

Cold probe: run the subject model with only the task + repo *name* in
an empty dir, tools disabled, forced best-guess with instructions to
append `(low-confidence)` to guesses (separates recalled from guessed).
Give the **public GitHub slug** when one exists — a memorized public
repo must be recognizable; a private repo's non-recognition is itself
the right signal. Judge the probe output against the reference with a
**structural/semantic criterion** ("structurally correct counts even
with different identifier names") because memorization shows as
right-shape answers, not verbatim. `is_clean = score < 0.70`
(permissive; only full semantic reproduction flags). Cache by
`sha256(task + reference + probe_version)`; run once per batch; **stamp
every stored row** with `leakage_score_cold / is_clean / raw_judge /
probe_version / error` so plain SQL can stratify. Batch stats then
recompute the entire scorecard **clean-only alongside overall** —
contaminated runs inflate baselines and mask real tool gains.

## 9. Statistics (small-N, honest)

- **Report median + IQR per condition, never point estimates.**
- **Comparison verdict** (explicitly heuristic, not a t-test):
  `delta = median_a − median_b`, `noise = (IQR_a + IQR_b)/2`;
  win only when `|delta| > noise + margin`. Purpose: block
  "5 vs 5.1 is better" claims. `insufficient` when either arm N<2.
  Sign-flip lower-is-better metrics so positive delta = win.
- **Pre-registration**: `primary_metric` + `minimum_meaningful_delta`
  (default 5.0) declared at run-request time, stamped on every row;
  comparisons test only the declared metric — blocks post-hoc "the one
  metric where we win" swaps.
- **G-theory variance decomposition** (method-of-moments, pure Python;
  N≈12–36 doesn't reward REML). Model
  `Y = μ + α_cond + γ_run|cond + δ_judge`:
  - σ²_run = MS_within (1-way ANOVA over conditions)
  - σ²_cond = max(0, (MS_between − MS_within)/n̄) — clamp flags
    "condition signal below run-noise floor"
  - **σ²_judge observed directly** as mean per-row judge-sample
    variance — the payoff of N judge samples per row
  - Generalizability `Eρ² = σ²_cond / (σ²_cond + σ²_run/n_runs +
    σ²_judge/n_samples)`; ≥0.80 reliable, ≥0.60 wide-CIs, <0.60 no.
  - Solve for runs needed to hit 0.80; if judge noise alone exceeds
    the budget, say "adding runs won't help — shrink judge variance."
  - `dominant_noise_source` = run vs judge; flag small batches
    (n_rows < 5·n_conditions).
- **Scenario discrimination** (IRT-borrowed):
  `between-condition stdev of medians / mean within-condition IQR`;
  ≥2.0 strong, <1.0 = weak evidence regardless of who "wins".
- **Scorer agreement**: |judge − keyword| > 10 flags divergent rows
  (diagnostic only).
- Protocol floor: **N≥3 batch for any published comparison**.
- **Capability probes** bypass the judge/variance stack entirely:
  precision@K / recall@K / first-hit-step over the first K
  Read/Grep/Glob calls vs must-open/must-not-open lists; "was the tool
  used, and *before the first edit*?" Return `{skipped: true}` (not
  zeros) when unobservable; `before_first_edit = None` when the agent
  never edited, so non-editing evals aren't inflated.

## 10. Results storage that worked

One denormalized SQLite table (`eval_results`, WAL), additive
idempotent migrations (`ALTER TABLE` in try/except), INSERT OR REPLACE
keyed `<run_dir>-<condition>` so re-import is idempotent — with the
lesson that partial re-upserts must read back previously-populated
columns first or they null them. A child `eval_probes(result_id,
probe_name, result_json)` table exists *specifically so probe
definitions evolve without migrations*. Rows carry identity
(run/batch/tool/scenario/model/condition/cto/reasoning), raw telemetry
(turns, tool calls, token classes incl. cache read/create, cost,
duration, per-tool breakdown JSON), both scores + vs-control ratios,
judge block (score/stdev/reliable/samples JSON/cost/elapsed),
pre-registration, leakage block, `deliverable_status
∈ {success, degraded, failed}`. Wart to avoid next time: duration
stored as display text ("2.3m") and re-parsed downstream.

## 11. Methodology fingerprinting (comparability contract)

`methodology_hash` = 12-hex prefix of SHA256 over canonical-JSON of the
framework **contract, not implementation**: framework version, contract
versions, the serialized condition matrix, whitespace-normalized hashes
of prompts.py + scoring.py, and a hash of **every** tool manifest.
Same hash ⇒ runs directly comparable; different ⇒ not, by definition.
Golden snapshots committed per hash; diff tool explains why a hash
flipped; adding a manifest is a methodology change even if unused;
adding a fingerprint input key is itself a version bump.

## 12. Anti-gaming discipline (kept results honest)

- The Cardinal Rule test: "Would I make this exact change if the eval
  didn't exist?" Causal arrow must be tool-improvement → observed
  score change, never score-low → tweak.
- **A mandated audit trail of *rejected* proposals**
  (`docs/architecture/eval-tuning-rejected.md`, kept in-repo):
  each entry = proposal / why it would raise a score / why rejected /
  what to do instead. Highlights: prompt-tightening rejected because a
  wide discoverability gap **is the honest signal**; schema-as-
  scaffolding rejected because malformed JSON is itself the
  production-relevant diagnostic; an eval-detecting env-var "boost
  mode" rejected as textbook overfitting whose sentinel is itself a
  leakage path.
- `objective`/`constraints` are rendered into the human report header
  but **never into agent prompts** — inserting them would hand the
  agent the rubric.
- Prompts come from one unit-tested builder, hints live in the tool's
  manifest, substituted once — no per-run hand-editing.
- Contamination guard both directions: control clone scanned for tool
  artifacts before launch; global skill dirs checked absent.
